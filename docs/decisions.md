## 4. 상태머신 (`:domain`, P1)

| # | 항목 | 결정 (2026-11-09) |
|---|---|---|
| S1 | 안내 문장 | **"{위치} 깜빡이는 {guideText} 버튼을 누르세요"**. 설계서의 "{guideText}를"은 HOT · ICE 같은 글자에서 을/를을 정하기 어려워 "버튼을"로 고정. 글자가 이미 "버튼"으로 끝나면 덧붙이지 않음 |
| S2 | 늦게 온 결과 | 번호표(ticket)로 구분해 무시 (종료 뒤 서버 응답, 옛 화면에 대한 응답 등) |
| S3 | 에코 방지 | ASKING은 질문을 **다 읽은 뒤**(`SpeechFinished`)에만 LISTENING으로 |
| S4 | 화면 전환 감지 | `screenChanges` + 다른 screenId의 스냅샷 둘 다. 새 화면 스냅샷이 이미 있으면 SCANNING 없이 바로 묻기 |
| S5 | 하이라이트 따라가기 | 같은 화면의 새 스냅샷마다 버튼 위치 갱신 (위치가 바뀌었을 때만 `Highlight`) |
| S6 | 묻는 사이 화면 전환 | 그 응답은 버리고 새 화면으로 다시 묻기. 답을 못 받은 발화는 다시 보냄 |
| S7 | UNKNOWN 응답 | 이유를 읽고 WAIT_CHANGE. 15초 뒤 다시 읽는 대신 **최신 화면으로 다시 묻기** (스냅샷마다 묻지 않게) |
| S8 | 오래된 화면 | `screenChanges`로 옛 화면 스냅샷을 버림. 시간 기준 만료는 필요하면 추가 |

2일차에 정할 것
- 진행 중(IDLE이 아닐 때) "말하기" 버튼: 지금은 무시. 다시 말하기(목표에 이어 붙이기)로 할지 결정
- 15초마다 다시 읽기의 횟수 제한: 지금은 제한 없음. 현장 테스트 뒤 결정

## 8. 3일차 실구현 시험 (P1, 2026-11-11 ~ 12)

| # | 항목 | 결정 |

| D1 | LLM | **Gemini 무료로 확정** (T4의 결론, 설계 때 팀 결정). 새 키는 `gemini-2.5-flash-lite`를 못 써서(404) **`gemini-3.5-flash-lite`**. temperature는 보내지 않음(Gemini 3은 낮추면 번호 칸에 문장이 섞임) · `targetId`를 이번 후보 번호로 묶음(enum) · 모든 칸 required + nullable(질문 칸을 건너뛰던 문제). 무료 한도는 **모델당 분당 15회**, 지연은 보통 1~2초에 가끔 5초 넘음 |

### 다음 (P1 제안)

Gemini 무료(lite)는 쉬운 판단(장바구니 → 결제하기, 다른 분류 → 커피 탭)은 맞히지만 "다른 메뉴가 눌렸는지"는 놓치고, 1~5초씩 걸린다. → **키오스크 하나(메가커피)의 화면 지도**를 서버에 넣는다: 고정 문구로 화면을 알아보고 화면별 다음 행동을 정해 두어 LLM 없이 즉시 안내, LLM은 말 이해와 지도에 없는 화면에만. 화면별 캡처를 받아 진행.

## 11. 사진을 보고 판단하는 기본 안내 (P1, 2026-11-13 밤, `feat/p1-photo-haiku`)

"인식 · 주문 흐름 · 오버레이가 다 잘 안 된다"는 시험 소감의 가장 큰 원인을 **AI가 화면을 글자 목록으로만 본다**는 점으로 보고,
기본 안내도 카메라 사진을 보게 바꿨다. AI는 결제한 Claude(Haiku 5.5, 생각 끔)를 쓴다. 바꾸기 전 기능 목록은 [features.md](features.md).

| | 무엇 | 바꾼 것 · 근거 |
|---|---|---|
| S1 | 모델 | **Claude Haiku 5.5, 생각 끔.** 같은 19장면(사진 + 글자)을 단독 프롬프트로 비교: Haiku 생각 끔 18/19 · 중앙값 1.50초 · 회당 약 $0.00035, Haiku 생각 낮음 16/19, Sonnet 5.5 생각 끔 19/19 · 중앙값 2.15초(가끔 9.9초) · 회당 약 $0.0071(20배). Sonnet은 한 장면 더 맞히지만 느리고 들쭉날쭉해서 6초 안에 답해야 하는 앱에 안 맞는다 |
| S2 | 기본 안내도 사진 | 앱이 이미 보내던 사진(`image`, 긴 변 960px)을 기본 안내에서도 AI에 같이 보낸다 (`PHOTO_GUIDE`, 기본 켬 · 끄면 예전처럼 글자만, 앱은 그대로). 사진 규칙(`PHOTO_NOTE`): 앞에 뜬 창만 · 직전 단계가 맞게 됐는지 사진으로 확인 · 글자가 깨지면 사진을 믿기 · 이름이 같은 메뉴만(아메리카노 ≠ 카페라떼) · 목표 메뉴가 없으면 분류 탭 · 다른 메뉴의 옵션 창이면 닫기 · 두 잔 이상이면 담기 전에 + · 삭제 확인 창은 취소. 글자 읽기가 아무것도 못 읽어도 사진이 있으면 AI에 묻고, '안 보이는 버튼' 규칙(`hidden_button`)은 사진이 있으면 건너뛴다. 후보는 위 탭 · 아래 진행 버튼까지 30개로 넓힌다 |
| S3 | 목록에 없는 버튼 | 답 형식이 '목록 안 번호'만 허용하면, 사진에서 결제하기를 보고도 글자 읽기가 놓친 그 버튼 대신 아무 칸(전체 · 연하게)이나 골랐다(도움 모드와 같은 문제) → `MISSING`을 허용한다. 말한 이름과 고른 칸 글자가 다르면 칸을 버리고, 그 이름을 글자 전체에서 다시 찾는다(깨진 글자 '결재하기' 포함, 같은 이름이 여럿이면 AI 상자와 가까운 칸). 없으면 사진 상자로 가리킨다 (`_photo_pick`) |
| S4 | 노란 칸 = 버튼 전체 | 글자 읽기는 글자 상자만 줘서 결제하기 · 탭 같은 버튼은 테두리가 글자에만 맞았다(메뉴 칸만 그림 · 이름 · 가격을 감쌌다). 사진을 볼 때는 AI가 고른 버튼의 **전체 상자**를 항상 받는다. 그 버튼 글자 상자의 가운데를 품을 때만 응답 `box`에 싣고(글자 상자까지 넓혀서), 앱은 글자 상자 대신 이 칸을 그리며 글자 상자에 붙여 이동 · 배율만큼 따라간다(`HighlightArea.button` · `follow`). 사진과 글자 읽기는 다른 순간이라 어긋난 상자는 버린다. 계약 `box`의 뜻을 넓혔다(선택 필드라 예전 앱은 무시) → **팀 확인 필요** (contract.md 3.2) |
| S5 | 사진 좌표 | Claude는 픽셀 좌표가 정확하다 → 질문에 사진 크기를 적고 [왼쪽, 위, 오른쪽, 아래] 픽셀로 받는다. 예전 Gemini식 0~1000 [위, 왼쪽, 아래, 오른쪽]은 크기를 모를 때만. 도움 모드 안내문은 예전 형식으로 남아 질문 끝의 픽셀 안내와 어긋나 있었다 → 맞췄다 |
| S6 | 빠른 길 | 사진을 볼 때는 쓰지 않는다: 글자만 보고 골라서 버튼 전체 상자도, 사진에만 보이는 선택 표시(✓)도 모른다. 그 경우 AI를 한 번 더 부른다(약 1.2초) |
| S7 | 사진 개인정보 | 적립(전화번호 숫자판) · 카드 화면이면 사진을 버린다: 앱이 글자에서 번호를 지워도 사진에는 남는다 |
| S8 | 고친 버그 | ① 적립 창 닫기: '×'가 글자 정리 뒤 빈 낱말이 되어 숫자판 '←'(지우기)를 닫기로 골랐다 → 기호는 원래 글자로 비교 ② `pillow`가 requirements에 없어 격자 찾기가 조용히 꺼지고 서버 테스트 4개가 실패했다 → 추가 |
| S9 | 평가 | `server/scripts/photo_eval.py`: 연습 키오스크 17장면(Chrome으로 찍어 앱과 같은 960px · JPEG 70) + 웹캠으로 찍은 실제 화면 2장(로컬 전용, 저장소에 안 올림)을 **실제 서버 판단 경로**에 넣는다. 글자 읽기 정상 / 불량(버튼 30% 빠짐 · 비슷한 글자로 바뀜 · 가격 깨짐 · 그림 버튼 못 읽음) × 사진 끔 / 켬. 결과는 아래 표 |
| S10 | 남은 것 | ① Haiku 5.5는 무작위성(temperature)을 바꿀 수 없어(1이 아니면 400) 같은 장면도 실행마다 답이 바뀐다 → 여러 번 돌려 평균을 본다 ② 웹캠 사진(비스듬 · 반사)은 상자가 빗나가는 장면이 남았다 ③ 실제 폰 확인 ④ 도움 모드 · 규칙으로 고른 버튼(적립 닫기 등)은 아직 글자 상자 · 메뉴 칸 |

평가 결과 (19장면을 3번씩 돌린 평균, 2026-11-13):

| 조건 | 사진 끔 (예전, 글자만) | 사진 켬 (이번) |
|---|---|---|
| 글자 읽기 정상 | 11.7/19 (62%) | **17.3/19 (91%)** |
| 글자 읽기 불량 | 7.3/19 (38%) | **15.0/19 (79%)** |
| AI 응답 중앙값 (같은 시간대, Claude가 붐빌 때) | 1.8~1.9초 | 1.9초 |
| 노란 칸이 실제 버튼과 겹친 비율 (IoU 중앙값, 맞힌 장면) | — (글자 상자) | 0.93 (정상) · 0.94 (불량) |

- 한가할 때 AI 응답은 1.2~1.5초였다 (같은 날 저녁 측정). 사진을 붙여도 같은 시간대의 사진 끔과 거의 같다.
- **상자를 항상 받기 vs 목록에 없을 때만** (같은 시간에 3번씩, 마지막 규칙 한 줄 전): 정상 17.0 vs 16.0 · 불량 14.3 vs 13.3 → 항상 받는다. 처음엔 규칙끼리 부딪혀('안 보이면 UNKNOWN' vs '분류 탭을 고르라') 항상 받기가 15.3 vs 16.7로 낮았다 → 사진 규칙에 '대신'을 분명히 적어 풀었다.
- 남은 실패: 다른 메뉴의 옵션 창(B04)에서 "닫기를 눌러 주세요"라고 말은 맞게 하지만 칸을 짚지 않고 되묻는다 · 웹캠 사진 1장(C02)은 상자가 버튼을 비껴간다 · 글자 불량에서 '커피' 탭이 안 읽힌 장면(B01)은 탭 대신 "안 보여요" · 샷을 고른 옵션 창(A03, 불량)에서 담기 대신 다른 옵션을 더 묻는다.

## 12. 도움 모드 기본 · 화면 번호 안정화 · 어르신 몫의 선택 (2026-11-14)

실기기(카페 키오스크 · PC 화면 시험)에서 나온 문제를 **원인부터** 고친 결정들이다. 각 항목은 로그로 원인을 확인하고, 고친 뒤 같은 방식으로 다시 재서 비교했다.

| | 무엇 | 바꾼 것 · 근거 |
|---|---|---|
| T1 | 도움 모드가 기본 | 화면이 바뀔 때마다 앱이 혼자 설명하던 방식은 같은 말을 반복하고 말이 끊겼다. **물어볼 때만 답한다**: 앱 `kl.helpMode` · 서버 `HELP_MODE` 기본 true. 자동 안내는 둘 다 false |
| T2 | 안내 음성 중 구슬로 끊기 | 말하는 중(파란 구슬)에 누르면 음성을 멈추고 노란 칸은 유지, 듣기는 시작하지 않는다. 2026-11-13 "말하는 중엔 끼어들 수 없다" 규칙을 요청으로 바꿈 (`SessionStateMachine.interruptSpeech`) |
| T3 | 화면 번호 기준 = 지속 글자 | 정지 화면 하나가 s1→s2→s3으로 바뀌던 원인은 기준을 **지금까지 본 가장 큰 프레임**으로 키운 것(잡음 글자가 박제). 최근 12프레임 중 60% 이상 읽힌 글자만 기준으로 하고 "그 글자가 아직 보이는가"(포함 비율)로 판단. 긴 글자는 길이 비례 오타 허용. 합성 잡음 9개 설정 × 40시드에서 정지 화면 오탐 10~40/40 → 0~2/40, 진짜 전환 정확 포착 0~26/40 → 23~40/40 |
| T4 | 방어막을 되돌림 | 앱 쪽에서 "글자가 겹치면 같은 화면"으로 막는 휴리스틱을 먼저 넣었다가, **실제 손떨림 녹화 재생 테스트**가 진짜 전환까지 막는 것을 잡아 전부 되돌렸다. 원인은 화면 번호 쪽(T3)에서 고친다 |
| T5 | 어르신 몫의 선택은 되묻는다 | AI가 말하지 않은 선택(예약번호 ↔ 여권 등)을 고르는 일을 막는다. 낱말 목록 대신 **모델이 `userChoice`(named · delegated · not_stated)를 직접 적게** 하고, 서버는 결정적인 조건(선택지 여럿 · 진행/동의 버튼 제외)만 본다 |
| T6 | 설명 문장 전달 · 동의 버튼 | 기본 경로가 AI의 설명(`message`)을 응답에 싣지 않던 것을 `say`로 전달. 동의 · 약관 버튼은 설명 없이 안내하지 않는다 (공통 출구 `_finish`) |
| T7 | 서버는 번호만, 위치는 앱이 | 서버 응답에는 좌표가 없다. 번호(`targetId`)로 앱이 **최신 프레임에서 같은 칸을 다시 찾아** 그린다 (흔들림 대응). 후보 밖 번호는 서버가 거른다 (화이트리스트) |
| T8 | Cloud Run 배포 | 폰만으로 동작하도록 서울 리전에 배포 (`server/deploy/`). 키는 Secret Manager에만. Cloud Run 앞단이 `/healthz`를 가로채므로 키 없는 요청의 401로 확인 |
