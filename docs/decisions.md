## 4. 상태머신 (`:domain`, P1)

| # | 항목 | 결정 (2026-11-09) |
|---|---|---|
| S1 | 안내 문장 | **"{위치} 깜빡이는 {guideText} 버튼을 누르세요"**. 설계서의 "{guideText}를"은 HOT · ICE 같은 글자에서 을/를을 정하기 어려워 "버튼을"로 고정. 글자가 이미 "버튼"으로 끝나면 덧붙이지 않음 |
| S2 | 늦게 온 결과 | 번호표(ticket)로 구분해 무시 (종료 뒤 서버 응답, 옛 화면에 대한 응답 등) |
| S3 | 에코 방지 | ASKING은 질문을 **다 읽은 뒤**(`SpeechFinished`)에만 LISTENING으로 |
| S4 | 화면 전환 감지 | `screenChanges` + 다른 screenId의 스냅샷 둘 다. 새 화면 스냅샷이 이미 있으면 SCANNING 없이 바로 묻기 |
| S5 | 하이라이트 따라가기 | 같은 화면의 새 스냅샷마다 버튼 위치 갱신 (위치가 바뀌었을 때만 `Highlight`) |
| S6 | 묻는 사이 화면 전환 | 그 응답은 버리고 새 화면으로 다시 묻기. 답을 못 받은 발화는 다시 보냄 |
| S7 | UNKNOWN 응답 | 이유를 읽고 WAIT_CHANGE. 15초 뒤 다시 읽는 대신 **최신 화면으로 다시 묻기** (스냅샷마다 묻지 않게) |
| S8 | 오래된 화면 | `screenChanges`로 옛 화면 스냅샷을 버림. 시간 기준 만료는 필요하면 추가 |

2일차에 정할 것
- 진행 중(IDLE이 아닐 때) "말하기" 버튼: 지금은 무시. 다시 말하기(목표에 이어 붙이기)로 할지 결정
- 15초마다 다시 읽기의 횟수 제한: 지금은 제한 없음. 현장 테스트 뒤 결정

| V9 | 분석 해상도 | CameraX 기본 640×480에서는 휴대폰에 띄운 키오스크 화면의 메뉴 이름을 거의 못 읽음(글자 13개 · 버튼 11개) → **1280×960 목표**(`ResolutionSelector`, 4:3, 지원 안 하면 가장 가까운 낮은 해상도). 같은 화면에서 **글자 32개 · 버튼 29개**, 아메리카노 · 카페모카 · 에스프레소 등 메뉴 이름과 "주문하기"까지 읽음. 한 번 읽는 시간 중간값 29 → 41ms (에뮬레이터 + Mac 웹캠, 2026-11-11). 실기기에서 발열 · 배터리 확인 필요. P5 위치 확인 화면은 기본 해상도 그대로지만 종횡비가 같아 좌표 확인에는 영향 없음 |

### P1이 정할 것

| 항목 | 지금 상황 | 추천 |
|---|---|---|
| 채우기 / 맞추기 | 채우기(FILL) + 4:3이면 세로로 긴 폰(1080×2400)에서 분석 프레임 좌우 20%씩이 화면 밖, 아래 버튼판이 화면 아래 15~20%를 가림 (P5 계산) | 실기기에서 어르신이 비추는 모습을 보고 결정. 그 전까지 FILL 유지 |

참고: `VisibilityTracker`는 "안 보임"을 알린 뒤 **다른 버튼으로 바뀌어** 보이게 되면 "다시 보임"을 알리지 않는다. 받는 쪽은 이 신호를 상태로 쓰지 말고 "안 보일 때 한 번 안내"로만 쓰거나, 연결할 때 함께 고칠 것.
→ **고침 (P5, 2026-11-12)**: "안 보임"을 알린 뒤 보이는 다른 버튼으로 바뀌거나 하이라이트가 없어지면 `true`를 알린다. 이제 마지막으로 받은 값을 상태로 써도 된다 (overlay/README).

## 8. 3일차 실구현 시험 (P1, 2026-11-11 ~ 12)

팀원 브랜치(PR #6 · #7 · #8)를 `feat/p1-day3-integration`에 합치고, 에뮬레이터(Mac 웹캠으로 휴대폰에 띄운 키오스크를 비춤) + 진짜 음성 · 서버 · LLM으로 처음부터 끝까지 시험하며 고친 것. 포트 · 계약 JSON은 바꾸지 않았다.

| # | 항목 | 결정 |
|---|---|---|
| D1 | LLM | **Gemini 무료로 확정** (T4의 결론, 설계 때 팀 결정). 새 키는 `gemini-2.5-flash-lite`를 못 써서(404) **`gemini-3.5-flash-lite`**. temperature는 보내지 않음(Gemini 3은 낮추면 번호 칸에 문장이 섞임) · `targetId`를 이번 후보 번호로 묶음(enum) · 모든 칸 required + nullable(질문 칸을 건너뛰던 문제). 무료 한도는 **모델당 분당 15회**, 지연은 보통 1~2초에 가끔 5초 넘음 |
| D2 | 서버 지연 대비 | 2초 안에 답이 없거나 혼잡(503)으로 실패하면 **같은 요청을 하나 더 보내 먼저 온 답**(429 · 인증 오류는 안 함). LLM 대기 4 → 5초, 총 예산 5 → 5.5초 (앱 6초 안). 앱은 서버 실패 한 번에 세션을 끝내지 않고 "잠시만 기다려 주세요" → 3초 뒤 다시 묻기, **연달아 3번** 실패할 때만 끝냄 |
| D3 | 서버 연결 (Android 17) | 사설 IP(10.x · 192.168.x · `.local`)는 **`ACCESS_LOCAL_NETWORK` 런타임 권한**이 없으면 패킷이 조용히 버려져 6초 시간 초과 → 디버그 매니페스트 + 실행 중 요청 (`LocalNetwork.isLocal`). 실폰 연결: 같은 와이파이에서 서버 `--host 0.0.0.0` + `kl.serverUrl`에 노트북 IP + 이 권한, 또는 HTTPS 배포(render.yaml) |
| D4 | 음성 인식 | 오프라인 엔진(`EXTRA_PREFER_OFFLINE=true`)은 ko-KR 모델이 없으면 12/13번 오류 → **일반 인식기 온라인으로 폴백** (결정 #3의 실제 동작). 안내 중에도 "말하기"로 말을 보탤 수 있고(같은 세션 · 목표 · 이력 유지), 질문에 대답하다 인식이 실패해도 세션을 끝내지 않고 다시 묻는다 |
| D5 | 화면 구분 (`:vision`) | 같은 화면 확정 1.5% → 73%: 글자 오타 허용(편집 거리) · 가격 · 남은 시간 제외 · 히스테리시스(유지 0.45 · 새 화면 0.6 연속 두 번). 담은 목록 · 장바구니 안의 같은 메뉴는 고를 버튼에서 뺌. **옵션 창이 메뉴 위에 떠도 새 화면**: 카메라 움직임을 맞춘 뒤 원래 보이던 영역 안쪽에서 새 글자가 나타나고 있던 글자가 사라졌는지로 판단 (카메라 이동 · 손가락 가림은 아님) |
| D6 | 하이라이트 | 메뉴 칸 전체를 감쌈(이름 아래 가격이 있으면 칸으로 봄). 손가락에 가려 안 읽히면 주변 글자가 움직인 만큼 옮기고, 그것도 모르면 숨김 (휴대폰이 움직여 옆 메뉴를 가리키던 문제) |
| D7 | 흐름 (서버) | "누르기" 뒤 화면이 바뀐 메뉴를 기억해 빠른 길이 같은 메뉴를 되풀이하지 않음('다음' · '확인' · '담기'는 예외). 짧은 대답("네" · "아니요")은 빠른 길을 쓰지 않음("샷 추가?" → "아니요"가 '취소'로 눌림). 말에 없는 HOT/ICE · 추가 옵션 · 매장/포장 · 결제 수단은 먼저 묻기. 화면이 바뀌면 **화면 전체 글자로 무슨 화면인지 판단**(원하는 메뉴의 옵션 창 / 다른 메뉴 → 취소 / 다른 분류 → 분류 탭 / 장바구니 → 결제) |
| D8 | 진단 기록 | 서버 `DEBUG_PROMPTS=1`이면 요청 화면 · LLM 원답 · 결정을 서버 기록에 남김(개발용, 배포 금지). 앱 인식 기록에 화면 번호 · 새 화면 여부 |

### 다음 (P1 제안)

Gemini 무료(lite)는 쉬운 판단(장바구니 → 결제하기, 다른 분류 → 커피 탭)은 맞히지만 "다른 메뉴가 눌렸는지"는 놓치고, 1~5초씩 걸린다. → **키오스크 하나(메가커피)의 화면 지도**를 서버에 넣는다: 고정 문구로 화면을 알아보고 화면별 다음 행동을 정해 두어 LLM 없이 즉시 안내, LLM은 말 이해와 지도에 없는 화면에만. 화면별 캡처를 받아 진행.
