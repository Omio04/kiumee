# 키우미 기능 목록

기준: `feat/p4-help-mode-merged` 3d903c6 (2026-11-13 20:57, main 46078f2 + P4 42커밋). P1이 코드를 직접 읽고 정리했다 (2026-11-13).
이 브랜치(`feat/p1-photo-haiku`)에서 바꾼 것은 본문에 반영하고 **6장**에 모았다.
P5의 아직 합치지 않은 브랜치 4개는 맨 아래 "반영 안 된 것"에 따로 적었다.

## 0. 한눈에

- **무엇**: 어르신이 휴대폰 카메라로 키오스크를 비추고 말하면, 눌러야 할 버튼에 노란 테두리를 깜빡이고 음성으로 안내한다.
- **구성**: Android 앱(모듈 7개) + 판단 서버(FastAPI). 서버 AI는 기본 **Claude Haiku 5.5(생각 끔)**, Claude가 일시 오류면 Gemini가 대신 답한다.
- **판단 경로 두 갈래**
  - **기본 안내**: 글자 읽기(OCR) 결과 + 규칙 + AI로 다음 버튼 하나를 고른다. **AI는 카메라 사진도 같이 보고**(`PHOTO_GUIDE`, 기본 켬), 노란 칸은 사진에서 본 **버튼 전체**에 그린다 (6장).
  - **도움 모드**(`HELP_MODE`, 기본 꺼짐): 어르신이 물어보면 그 순간의 **사진**을 보고 답한다. 글자 목록에 없는 버튼은 사진 위치(박스)나 격자로 찾는다.
- **테스트**: 740개, 모두 통과 (core-model 5 · domain 88 · agent 24 · vision 74 · voice 23 · overlay 76 · app 40 · server 410). 3d903c6 기준은 domain 84 · server 392(그중 4개는 `pillow`가 없어 실패).

## 1. 쓰는 흐름 (어르신 입장)

1. 앱을 켜면 로딩 화면(키우미 캐릭터)이 뜨고, 카메라 · 마이크 권한을 받는다. 거절하면 이유와 "설정 열기"를 보여 준다.
2. 카메라 화면에서 키오스크를 조준 모서리 안에 담고, 아래 가운데 **마이크 구슬**을 눌러 말한다 ("아이스 아메리카노 한 잔").
3. 앱이 화면 글자를 읽어 서버에 묻고, 답에 따라 **노란 테두리 + 음성**("화면 왼쪽 위 아메리카노 버튼을 누르세요")으로 안내한다.
4. 누르면 화면이 바뀐 것을 알아채고 다음 단계를 다시 묻는다 (옵션 → 담기 → 결제 …).
5. 중간에 다시 말할 수 있다(말 보태기). 안내를 읽는 중에 말하면 멈추고 듣는다(말 끊기, 설정).
6. 결제 진행 · 완료 화면이 보이면 끝낸다.

## 2. 앱 (Android)

### `:app` — 조립 · 화면 (P1)
- **화면**: 카메라 미리보기, 마이크 구슬 버튼(상태별 색 · 숨쉬기 · 목소리 크기 파동 · 생각 중 호 · 말하는 중 소리 막대 · 끝나면 체크 · 문제 주황, 색이 부드럽게 바뀜), 조준 모서리(찾는 중 하양 → 글자를 읽으면 하늘색), 가장자리 비네트, 왼쪽 위 키우미 표시, 로딩 화면, 앱 아이콘 · 이름 "키우미".
- **카메라** (`camera/`)
  - 분석 1280×960, 미리보기 · 분석 같은 4:3
  - 노출 약 −0.5EV + 측광 영역을 받는 기기면 가운데 기준 노출 (`ExposureTuning`)
  - 흔들림에 강한 촬영 설정: 광학 손떨림 보정 · 프레임 속도 범위 (`StabilizationTuning`)
  - 흔들리는 프레임은 글자 읽기에 넘기지 않음 (`ShakeGate`)
  - 프레임마다 흔들림을 재서 노란 테두리를 따라가게 함 (`CameraMotionTracker` 연결)
  - 질문할 때 보낼 사진: 선명한 프레임만 0.8초마다 긴 변 960px · JPEG 70으로 최신 한 장 보관, 5초 넘으면 안 보냄, 디스크에 안 씀 (`FrameJpegCache`)
- **설정 스위치** (`local.properties`): `kl.serverUrl` · `kl.appKey` · `kl.helpMode`(도움 모드) · `kl.handsFree`(누르지 않고 계속 듣기) · `kl.sendImage`(사진 보내기) · `kl.bargeIn`(말 끊기) · `kl.showRecognition`(개발용 인식 표시)
- **기타**: Android 17 로컬 네트워크 권한 요청, 개발용 인식 표시(글자 네모 · 상태 줄), 그리기 속도 · 추적 실패 기록(KL_PERF).

### `:domain` — 상태 기계 (P1, 순수 Kotlin)
- **단계 10개**: 대기 · 듣기 · 생각(서버) · 화면 찾기 · 안내 · 화면 바뀌길 기다림 · 되묻기 · 끝 · 놓침 · 오류.
- **기본 흐름**: 말 → 화면 글자와 함께 서버에 묻기 → 안내(노란 테두리 + 음성) → 화면이 바뀌면 다시 묻기.
- **말 보태기**: 안내 중에도 마이크를 누르면 더 듣고 이어서 묻는다.
- **놓친 화면 전환**: 화면이 바뀐 걸 늦게 알면 다시 묻는다. 서버 실패는 3초 뒤 3번까지 다시 묻는다.
- **도움 모드**: 물어볼 때만 답하고 계속 듣는다. 손 안 쓰기면 버튼 없이 계속 듣는다.
- **찾기(seek)**: 서버가 "이 이름을 찾아 줘"라고 하면, 그 글자가 읽히는 순간 바로 노란 칸을 친다.
- **따라가기** (`HelpTracker`): 흔들려서 화면 번호 · 칸 번호가 바뀌어도 이름(깨진 글자 포함)으로 다시 찾아 붙고, 못 찾으면 주변 글자의 이동 · 배율만큼 옮긴다.
- **테두리 자리** (`HighlightArea`): 서버가 사진에서 본 **버튼 전체 칸**(`box`)을 주면 글자 상자 대신 그 칸을 그리고, 글자 상자에 붙여 이동 · 배율만큼 따라간다(글자와 어긋난 칸은 버림). 칸이 없으면 메뉴판처럼 "그림 + 이름 + 가격" 칸은 칸 전체, 그 밖은 글자 상자.
- **이름 맞추기** (`NameMatcher`): 서버와 같은 자모 n-그램 유사도로 깨진 글자를 맞춘다.
- **문장** (`GuideTextComposer` · `PositionPhraser`): "화면 오른쪽 아래 ○○ 버튼을 누르세요" 같은 쉬운 존댓말, 위치는 가로 · 세로 3등분.
- **시간 규칙** (`TimeoutPolicy`): 듣기 · 서버 · 화면 기다림 · 재시도 시간을 한 곳에서.

### `:agent` — 서버 통신 (P4)
- 계약 JSON을 외부 라이브러리 없이 만들고 읽는다 (`DtoMapper` · `Json`). 사진은 선택 필드 `image`.
- 전체 6초 제한, 실패를 어르신께 읽어 줄 종류로 나눔(입력 오류 · 인증 · 혼잡 · 서버 · 시간 초과 → 다음 행동을 알려 주는 한 문장).

### `:vision` — 화면 글자 읽기 (P2)
- ML Kit 한국어 글자 인식, 한 번에 하나만 처리하고 최신 프레임만 대기 (`VisionScreenAnalyzer`).
- 글자 거르기: 낮은 신뢰도 · 너무 작음 · 의미 없음 · **카드번호 · 유효기간 · 전화번호** (개인정보는 앱에서 먼저 지움).
- 종류 나누기: 가격 · 안내 문장(숫자 · 남은시간 등) · HOT/ICE 메뉴 · 버튼.
- 줄바꿈된 메뉴 이름 다시 잇기 (`OcrBlockLineMerger`), 담은 목록 안 메뉴 이름은 버튼에서 뺌 (`CartRegion`).
- 팝업 처리 (`SceneProcessor`): 적립 · 일회용품 · 주문 확인 · 결제수단 · 옵션 · 카드 승인 · 영수증 · 완료 · 알림창. 제목과 버튼이 또렷하면 창 안 버튼만 남기고, 제목만 보이면 버튼을 안내하지 않는다.
- 작은 닫기(X) 아이콘 찾기 (`CloseIconDetector`).
- 화면 구분 (`ScreenTracker`): 글자 집합 유사도 + 옵션 창처럼 화면 일부만 바뀐 것 감지 + 선택한 옵션 변화, 2프레임 확인.
- 사진 입력 디버그 모드 (`PhotoAnalyzer`).

### `:voice` — 듣기 · 말하기 (P3)
- 한국어 음성 인식: 기기 안 인식 우선, 한국어 모델이 없으면 온라인으로 바꾸고 그 사실을 7일 기억(첫 말 잘림 방지). 실패 시 1회 자동 재시도, 소리 크기를 마이크 파동에 전달.
- 음성 안내: 속도 0.85, 문장 단위로 나눠 읽음, 새 안내가 오면 이전 안내를 끊음.
- 울림 방지: 실제로 읽던 중일 때만 0.3초 기다린 뒤 마이크를 켬 (`EchoGuard`).
- **말 끊기** (`BargeInGate` · `BargeInMonitor`): 안내를 읽는 중 마이크를 열어(에코 제거 입력) 사람이 말을 시작하면 안내를 멈추고 듣는다.

### `:overlay` — 노란 테두리 (P5)
- 노란 테두리를 1.5Hz로 깜빡임(3Hz 이하, 완전히 꺼지지 않음), 처음 나타날 때 0.4초 동안 그려지며 짚음, 연한 반투명 선.
- 좌표 변환: 미리보기 크롭 방식(FILL_CENTER 등)에 맞게, 가려진 가장자리(버튼판 등)에 걸리면 안 보임으로 판단.
- 흔들림 따라가기: 밝기 격자로 화면 전체 이동을 추정해 테두리를 옮기고, 1초 넘게 못 따라가면 흐리게 (`GridMotionEstimator` · `TrackingHealth`), 위치가 바뀌면 부드럽게 이동 (`BoxSmoother`).
- 안 보임 신호(바뀔 때만 알림), 그리기 속도 측정, 개발용 인식 상자 그리기.

### `:core-model` — 공통 타입 · 포트 (계약 v1, 전원 승인)
- 좌표(0~1 정규화) · 화면 요소 · 스냅샷 · 안내 행동 6가지(누르기 · 밀기 · 기다림 · 되묻기 · 끝 · 모름) · 이력 · 요청 · 응답(`say` · `box` · `seek` 선택 칸) · 포트(카메라 · 화면 · 듣기 · 말하기 · 서버 · 테두리 · 흔들림 · 시계 · 로그).

## 3. 서버 (`server/`, FastAPI)

### 받는 곳
- `POST /v1/guide/next` 하나와 `/healthz`. 앱 키(`X-App-Key`) 확인, 요청 크기 제한(사진 포함 1MB), 메모리 속도 제한, 오류는 정해진 형식(상태 + 코드). `server/.env`를 직접 읽는다(명령줄 환경변수가 우선).

### 기본 안내의 판단 순서 (`agent.py`)
1. **개인정보**: 민감한 글자를 지우고, 하나라도 지웠으면 **사진도 버린다** (`privacy.py`). 적립(전화번호 숫자판) · 카드 화면이어도 사진을 버린다.
2. **어르신 말 정리**: 군말("어… 그…") 빼기, "그걸로 할게요" → 앞서 설명한 메뉴로 바꾸기 (`elder.py`).
3. **응답 캐시**: 같은 화면 · 목표 · 이력이면 바로 답.
4. **말투 규칙**(AI 없이): 도움 요청 · 그만 · 다시 말해 줘 · 화면에 없는 현금 결제.
5. **연습 키오스크 지름길** (`kiosk_flow.py`): 목표가 정확히 "아이스 아메리카노 한 잔"이면 규칙으로 결제까지 안내.
6. **결제 진행 · 완료 화면**이면 끝.
7. **화면 종류 확률** (`screen_type.py`): 먹고가기/포장 · 메뉴 · 옵션 · 주문 확인 · 일회용품 · 적립 · 결제수단 · 카드 · 끝. **키오스크 추정** (`kiosk.py`): 가게 · 종류(카페 · 햄버거 …). **화면 기억** (`screen_memory.py`): 무엇에서 무엇으로 바뀌었는지.
8. **적립 화면**은 요청이 없으면 닫기(X)로 건너뜀(닫기가 안 보이면 다시 비춰 달라고).
9. **안 보이는 버튼** (`hidden_button.py`): 하려는 일의 버튼(담기 · 결제하기)이 화면에 없으면 지어내지 않고 카메라를 조정하게 함. 사진이 있으면 건너뜀(AI가 사진에서 찾는다).
10. **메뉴 설명** (`menu_info.py`): "라떼가 뭐야?"에 AI 없이 답. "뭘 눌러야 돼요?"에 지금 고를 수 있는 것을 알려 줌 (`screen_guide.py`).
11. **후보 고르기** (`ranker.py`): 자모 n-그램 유사도로 후보 8개, 진행 버튼 가산. 사진이 있으면 위 탭 · 아래 진행 버튼까지 30개로 넓힘.
12. **빠른 길**: 확실하면 AI 없이 바로 누르기(같은 글자 여럿 · 이미 안내한 버튼 · 짧은 대답은 제외). 사진이 있으면 쓰지 않음(버튼 전체 칸 · 선택 표시를 모른다).
13. **AI 판단** (사진 + 글자, 사진이 없으면 글자만): 사진 규칙(`PHOTO_NOTE`)과 사진 크기(픽셀 좌표용)를 붙인다. 목록에 없는 버튼은 `MISSING` + 사진 상자. 목표 · 이력 · 후보 · 화면 글자 30개 · 진행 단계 요약(`progress.py`) · 눌렀는데 안 보임 / 비슷한 다른 메뉴 경고(`expectation.py`) · 화면 종류 확률 · 키오스크 추정 · 화면 변화. 1.6초 넘으면 같은 요청을 하나 더 보내 먼저 온 답을 씀, 형식 오류면 1회 재요청.
14. **검증과 안전장치**: 말한 이름과 고른 칸 글자가 다르면 칸을 버리고 이름으로 다시 찾기(깨진 글자 포함) → 없으면 사진 상자, 고른 버튼의 전체 상자를 `box`로(글자와 어긋나면 버림), 후보 밖 버튼 거절, 새 화면에서 못 정하면 고를 수 있는 것을 설명, 끝났다는 증거 없는 '끝' 거절, 고른 것 없이 '끝' · '결제'로 가지 않기, 앱이 뭔가 하는 듯한 말 지우기, 같은 말 반복 막기.

### 도움 모드 (`HELP_MODE=true`)
- 어르신 질문 + **사진** + 화면 글자로 답하고 "또 도움이 필요하세요?"로 이어 듣는다 (`help_mode.py`).
- 사진 위 후보마다 번호 그리기(Set-of-Mark, `SOM_MARKS`), OCR 오타 낱말 교정(`LEXICON_FIX`) — 둘 다 기본 꺼짐.
- 말한 이름과 고른 칸이 다르면 칸을 믿지 않음, 되돌리는 버튼(처음으로 · 취소)은 원할 때만, 어르신이 정할 선택은 칠하지 않음.
- **글자 목록에 없는 버튼**: AI가 사진에서 찾은 위치(`box`)로 가리킴 → 그래도 없으면 **격자(A1~F8) 사진**으로 칸을 고르고 확대해 한 번 더 (`som.py`, `GRID_LOCATE` · `GRID_ZOOM` 기본 켜짐) → 그래도 없으면 찾기(`seek`)로 넘김.
- 다른 키오스크로 옮겨 가면(직전 화면과 글자가 거의 안 겹침) 대화 기록을 비움.

### AI 연결 (`llm.py`)

## 4. 계약 (앱 ↔ 서버, `docs/contract.md`)
- 요청: `sessionId` · `utterance` · `goal` · `snapshot`(글자 · 종류 · 좌표 · 신뢰도) · `history`(최근 5개) · `image`(선택, base64 JPEG, 70만 자 이하, `kl.sendImage`로 끔).

## 5. 한계 · 반영 안 된 것 (P1 판단)
- **기본 안내는 사진을 쓰지 않았다** (3d903c6 기준, 사진은 도움 모드에서만). 이 브랜치에서 바꿨다 (6장, decisions.md 11장).
- **연습 키오스크 지름길** (`kiosk_flow.py`)은 "아이스 아메리카노 한 잔"에만 맞춘 시연용 규칙이다. 다른 메뉴 · 키오스크에는 쓰이지 않는다.
- **판단 순서가 길다**: 규칙 · 지름길 · 빠른 길 · 경고가 여러 겹이라, 어떤 경로로 답이 나왔는지 기록(`source`)을 봐야 알 수 있다.
- **사진 개인정보**: 서버는 민감한 글자가 읽힌 요청의 사진을 버리지만, 글자 읽기가 놓친 번호는 사진에 남을 수 있다.
- **기기 확인 필요**: 노출 낮추기 · 말 끊기 · 사진 박스 · 격자 찾기 · 버튼 전체 칸은 실제 폰에서 더 확인해야 한다.
- **P5 브랜치 4개 미반영**: `feat/p5-aim-hints`(다시 비추기 음성 안내), `feat/p5-lighter-border`(테두리 더 연하게), `feat/p5-lost-hide`(크게 놓치면 숨겼다 다시 짚기), `feat/p5-mic-listening-color`(듣는 동안 빨간 녹음 색).

## 6. 이 브랜치에서 바꾼 것 (`feat/p1-photo-haiku`, P1, 2026-11-13 밤)

근거 · 평가는 [decisions.md](decisions.md) 11장.
- **기본 안내도 사진을 본다**: 앱이 이미 보내던 사진을 AI(Claude Haiku 5.5, 생각 끔)가 글자 목록과 함께 본다 (`PHOTO_GUIDE`, 끄면 예전처럼 글자만). 앱 쪽은 바꿀 것이 없다.
- **노란 칸 = 버튼 전체**: AI가 사진에서 본 버튼 전체 상자를 받아, 앱이 글자 상자 대신 그린다. 글자 상자에 붙여 휴대폰이 움직이고 가까워지는 만큼 따라간다. 글자와 어긋난 상자는 버린다.
- **글자 읽기가 놓친 · 깨뜨린 버튼**: `MISSING` → 이름으로 글자 전체에서 다시 찾기(깨진 글자 포함) → 사진 상자. 한두 글자 깨진 이름(가드결제)은 사진에서 읽은 이름(카드결제)으로 말한다.
- **사진 규칙**: 앞에 뜬 창만 · 직전 단계 확인 · 이름이 같은 메뉴만 · 목표 메뉴가 없으면 분류 탭 · 다른 메뉴의 옵션 창이면 닫기 · 두 잔 이상이면 담기 전에 + · 삭제 확인 창은 취소.
- **사진 좌표를 픽셀로** (기본 안내 · 도움 모드), **사진을 볼 때 빠른 길 끔**, **적립 · 카드 화면 사진 버림**.
- **버그**: 적립 창 닫기가 숫자판 '←'를 고르던 것, `pillow` 누락(격자 찾기가 조용히 꺼지고 테스트 4개 실패).
- **평가 도구**: `server/scripts/photo_eval.py` (연습 키오스크 + 웹캠 사진, 사진 끔/켬 × 글자 정상/불량, 노란 칸 겹침).
  결과(19장면 3번 평균): 글자 정상 11.7 → **17.3**/19, 글자 불량 7.3 → **15.0**/19, 노란 칸과 실제 버튼 겹침 0.93.
- **계약**: 응답 `box`의 뜻을 넓혔다(글자 목록의 버튼이면 그 버튼 전체 칸). 선택 필드라 예전 앱은 무시한다 → 팀 확인 필요.
