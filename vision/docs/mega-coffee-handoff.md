# 메가커피 예시: P2 개선과 P1·P4·P5 연결 사항

> 2026-11-14 참고: 화면 구분 기준이 "최근 프레임에서 계속 읽히는 글자(지속 글자)" 방식으로 바뀌었다 ([vision/README.md](../README.md) 6번). 아래 Jaccard 수치는 이 문서를 쓸 당시 기준이다.

사용자가 제공한 10장으로 관찰한 흐름이다. 사진의 문구는 데이터로 읽었으며 앱의 실행 지시로 취급하지 않았다.
**아이스 아메리카노 / 연하게 / 카드결제는 예시에서 사용자가 직접 고른 값이며 고정 선호나 기본값이 아니다.**
이 자료는 OCR·요소 분류·화면 전환 검증용 관찰 자료이며 고객의 주문 순서나 선택 기준이 아니다.
상품·맛·샷·매장/포장·일회용품·결제수단을 예시에서 추정하지 않는다.
사용자가 이미 명확하게 말한 선택은 반영한다. 무엇을 선택할지 모르는 사용자에게는
현재 화면의 선택지와 뜻을 쉬운 말로 설명하고 원하는 것을 확인한 뒤 해당 버튼을 안내한다.
단순히 “고르세요”를 반복하거나 모른다는 답변에 임의의 기본값으로 진행하지 않는다.
적립은 사용자의 요청대로 건너뛴다.

질문 예시:

- 상품: 현재 화면에 실제 보이는 음료 종류를 설명하고, 어떤 음료를 원하는지 확인한다.
- 맛·샷: 현재 화면의 옵션 뜻을 설명한다. 예를 들어 '연하게'가 보이면 “연하게는 커피 맛을 덜 진하게 하는 옵션이에요. 진한 맛이 부담스러우세요?”처럼 선호를 확인한다.
- 매장·포장: “매장에서 드시나요, 포장하시나요?”
- 일회용품: “필요한 일회용품을 골라주세요.”
- 결제: “결제수단을 골라주세요.”

실제 화면에 있는 선택지만 안내한다. 답변 전에는 연하게·샷 추가·선택안함 등을 임의로 결정하지 않으며
주문담기·선택완료로 넘어가지 않는다. 영상 속 클릭 이력은 현재 사용자의 답변을 대신하지 않는다.

## P2에서 반영한 것

- `MlKitOcrEngine`이 블록 번호를 유지하고 `OcrBlockLineMerger`가 같은 블록·겹치는 열의 짧은 줄바꿈만 합친다.
  예: `(ICE)헤이즐넛아메리카` + `노`. 다른 상품 열, 다른 블록, 가격 줄은 합치지 않는다.
- 가격 분류가 `+0원`, `+600원`, `+1,200원`을 처리한다. 카운트·합계·안내문·ONLY ICE 배지는 TEXT다.
  ICE/HOT 이름은 서로 다른 상품으로 남기고 OCR 원문을 목표 상품명으로 임의 교정하지 않는다.
- 선택된 옵션 요약 띠의 `연하게`와 실제 옵션 타일의 `연하게`를 구분한다.
  장바구니 행의 상품명은 TEXT로 내려 같은 이름의 메뉴 타일을 대신 선택하는 일을 줄인다.
- 적립·일회용품·주문 확인·결제·상품 옵션 팝업은 제목과 추가 증거가 함께 맞을 때 영역을 추정한다.
  팝업 밖 배경 메뉴는 내보내지 않아, 배경이 거의 같아도 팝업 전환이 Jaccard 판정에 반영된다.
- 적립 팝업은 제목 + 적립 버튼 + 숫자 키패드가 확인되어야 인식한다.
  기본 건너뛰기 모드에서는 적립·숫자를 버튼 후보로 내보내지 않는다.
  `SceneProcessor(rules = listOf(LoyaltyDialogRule(skipLoyalty = false), ...))`로 정책을 주입할 수 있다.
- `CloseIconDetector`는 적립 제목 오른쪽 근처에서 실제 어두운 원과 밝은 X의 네 대각선 획을 확인한다.
  검증된 아이콘에만 실제 기호 `×`와 정규화 좌표를 부여한다. +·원·반사광을 거부하며, 보이지 않는 X를 고정 좌표로 만들어내지 않는다.
  회전 보정된 밝기 평면을 직접 읽고 전체 이미지 변환이나 새 모델 다운로드는 하지 않는다.
- 전화번호 전체는 필터로 제거한다. 로그에는 원문이나 번호를 남기지 않는다.
- 119초→118초 같은 순수 카운터 변화는 화면 전환 서명에서 제외한다.

공용 모델·포트·JSON 형식은 그대로다. 추가 관찰 메타데이터는 vision 내부에만 있다.

## 다른 담당에게 필요한 연결 (아직 이 모듈에서 실행하지 않음)

| 담당 | 연결 사항 |
|---|---|
| P1 | 사용자가 실제 말한 목표와 선택만 유지하고 `SnapshotSource`를 세션에 연결한다. 질문 후 응답을 기다리며, 사진만 있는 테스트 앱에는 주문 안내 전체 세션이 없다. |
| P4 | 사용자가 무엇을 원하는지 모르면 실제 화면의 선택지와 뜻을 쉽게 설명하고 ASK_USER로 선호를 확인한다. 대답이 오기 전 다음 TAP을 결정하지 않는다. 예시의 아이스·연하게·카드결제를 기본값이나 고객 선택 기준으로 쓰지 않는다. 적립 화면에서는 실제 스냅샷의 `×` 후보를 선택한다. 후보가 없으면 UNKNOWN/재촬영 안내로 처리한다. |
| P5 | 선택된 후보의 회전 보정 정규화 rect를 프리뷰 좌표로 변환한다. `×`도 글자 버튼과 같은 방식으로 하이라이트한다. |

P2는 키오스크를 자동으로 누르거나 서버의 다음 행동을 대신 결정하지 않는다.
이 모듈 변경만으로 전체 주문 안내나 적립창 자동 건너뛰기까지 연결되었다고 볼 수 없다.
매장/포장, 일회용품 기본값을 임의로 선택하지 않았다.
적립창 다음 화면과 카드 단말기 안내는 예시가 없어 추정하지 않는다.

같은 옵션 화면에서 체크만 바뀌거나 장바구니 수량만 늘어나는 경우에는
텍스트 Jaccard가 0.6 아래로 떨어지지 않아 `screenChanges`가 발생하지 않을 수 있다.
P1·P4는 같은 screenId의 최신 스냅샷·선택 요약과 안내 이력을 함께 확인해 다음 요청을 이어가야 한다.
이 경우를 억지로 새 화면 이벤트로 바꾸거나 공용 계약에 선택 상태 필드를 추가하지 않았다.

## 검증의 범위

2026-11-09 로컬 최종 검증: 테스트 **44개 통과 / 실패 0 / skip 0**,
Android lint **오류 0 / 의존성 업데이트 알림 1**, 테스트 앱 APK 빌드 성공.
실제 적립 이미지의 X 원 영역 검출 상자는 정규화 좌표
`(0.806, 0.241)–(0.869, 0.271)`이었다. 제목 영역은 사람이 지정한 값이다.
실기기 OCR 정확도나 전체 주문 흐름 성공률을 뜻하는 수치는 아니다.

`MegaCoffeeExampleTest`는 사람이 예시를 보고 작성한 OCR 줄 입력으로 분류·팝업·전환을 검사한다.
이 테스트가 통과해도 10장에 대한 ML Kit OCR 재현율을 측정한 것은 아니다.

`CloseIconDetectorTest`는 합성 X·+·원·반사광 검증에 더해,
제공된 10번 이미지의 실제 밝기 픽셀과 사람이 표시한 제목 영역으로 X 위치를 검사한다.
PNG와 밝기 데이터는 `vision/.local/mega`에만 보관하며 Git 대상에서 제외한다.
로컬 사진이 없는 환경에서는 해당 사진 테스트 1개만 skip된다.

```powershell
./vision/tools/extract-example-luma.ps1
./vision/tools/verify.ps1
```

사진에는 iPhone Photos UI·위치·개인 갤러리 썸네일이 함께 보인다.
팀에 공유할 실측 세트는 키오스크만 보이는 원본 프레임으로 준비하는 편이 좋다.
추가 실측: 글자 인식률, 제목이 줄바꿈/누락된 경우, 반사·기울기, 조명 변화에서 X 오인율,
실제 Android 프레임의 회전과 좌표, P4·P5 연결 후 질문/닫기 안내 전체 흐름.
